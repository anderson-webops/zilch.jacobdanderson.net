# Zilch 1.4.5

This release supersedes the unpublished `v1.4.4` candidate after its Linux ARM64
artifact gate found that the isolated promotion fixture had no account-name
database. Privileged ownership operations now use the numeric root UID and GID,
preserving `0:0` ownership without depending on name-service resolution.

It retains the complete `v1.4.4` deployment hardening:

- exact, mode-bound runtime artifact manifests and clean unpacked-artifact tests;
- root extraction with runtime and Nginx readability checks while the private
  preparation marker remains root-only;
- exact `v1.4.1` rollback compatibility through `/api/health` and the historical
  Nginx contract, while all newer releases require `/healthz` and `/readyz`;
- artifact-only activation with tested rollback and recovery behavior; and
- protected helper, archive, symlink, identity, and source-boundary checks.

Validation covers the frozen Node 24.18.1 and npm 12.0.2 dependency graph, full
and production audits, registry signatures, 22 Linux ARM64 native packages,
lint, types, 85 automated tests, both builds, deployment and Netlify contracts,
the production-only API install, accessibility smoke checks, the disposable
privileged host, and the exact Linux ARM64 release artifact.

This is source delivery only. Production activation remains a separately
authorized server operation, and local origin probes are not independent WAN
acceptance.
