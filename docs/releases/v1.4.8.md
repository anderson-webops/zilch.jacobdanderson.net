# Zilch 1.4.8

## Version-aware recovery and reproducible artifacts

This release keeps production activation artifact-only while correcting the
source workflow exposed by the September 21 recovery review.

- Artifact-era rollback and retained-release restoration now select the exact
  root-owned helper contract and Nginx template for the target release. The
  newest trusted verifier performs validation; older helper code is never
  executed.
- A bounded `--restore-retained` operation lets an outer acceptance layer
  restore an already protected release from local evidence when GitHub is
  unavailable. It does not permit a source rebuild, archive rewrite, or a
  relaxed new-candidate check.
- The isolated regression covers v1.4.3 to v1.4.7 origin promotion, a failed
  independent-network gate, and restoration of v1.4.3 with its own helper and
  Nginx contract. A separate failure case proves inner rollback to an
  artifact-era release.
- Artifact packing and recovery fixtures cover umasks `0027` and `0077`. The
  newly written runtime manifest is explicitly normalized to `0644` and the
  complete tree is revalidated before packaging.
- The current Nginx template uses `http2 on` instead of the deprecated
  `listen ... http2` parameter. The exact v1.4.1 historical rollback template
  remains byte-for-byte unchanged. CI validates the current syntax with a
  fingerprint-verified package from the official Nginx repository because
  Ubuntu 24.04's distribution package predates the standalone directive.
- Documentation distinguishes deterministic local origin acceptance from
  independent WAN acceptance. NAT hairpin behavior is never reported as
  outside-client evidence.

The direct host remains `zilch-site` on `127.0.0.1:3018` with Node 24.18.1.
NP Service Request remains on `127.0.0.1:3016`. This source release does not
change DNS, credentials, databases, firewall policy, or production state.
