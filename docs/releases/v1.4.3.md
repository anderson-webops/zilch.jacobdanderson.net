# Zilch 1.4.3

## Reproducible and bounded runtime

- The Linux ARM64 release workflow now builds one exact runtime archive, records
  every required path and hash, tests the unpacked artifact without source or
  development dependencies, and publishes an acceptance receipt with the
  archive checksum and source identity.
- Root-controlled promotion verifies the protected archive, digest, full commit,
  trusted paths, immutable release tree, and runtime identity before activation.
  Interrupted or failed activation restores the prior release and records any
  degraded recovery state without trusting candidate-owned helper code.
- The writable npm cache remains service-owned beneath a root-owned parent, so
  the service account cannot swap its path during a privileged helper upgrade.
  The tag gate exercises that boundary with a concurrent attacker fixture.
- Linux ARM64 GNU and musl native optional packages are explicit in the locked
  dependency graph so a clean production build does not depend on the machine
  that generated the lockfile.
- The loopback-only API now caps retained rate-limit identities and open
  connections, handles repeated shutdown signals safely, and exposes minimal
  no-store `GET`/`HEAD` health and readiness probes.
- Browser game and setup data are bounded before parsing and validated with
  limits on nested event, message, identifier, and player arrays.
- Dependency locks were refreshed under Node 24.18.1 and npm 12.0.2 with no
  known full-graph or production advisories.

Local validation covered clean locked installation, package signatures, full
and production audits, lint, types, 82 automated tests, both builds, deployment
output, Netlify runtime, an isolated production API install, accessibility,
direct-runtime behavior, and a 102,000-identity storage stress comparison. The
tag workflow is the authoritative Linux ARM64 artifact and promotion-recovery
gate.

The earlier `v1.4.2` tag stopped safely in its disposable-host acceptance job
before artifact packaging because the hosted runner's `/opt` parent did not meet
the production ownership policy. This release hardens that test-only parent and
does not move the prior tag.

This is a source release. It preserves Zilch on `127.0.0.1:3018` and does not
move or modify NP Service Request on port `3016`. The production host must
separately activate the accepted `v1.4.3` artifact before the live site uses
these changes.
