# Zilch 1.4.9

## Version-aware recovery and mode-preserving artifacts

This release carries forward the reviewed recovery changes from the rejected
1.4.8 candidate and corrects the final copied-artifact fixture found by its
Linux ARM64 release gate. No 1.4.8 release assets were published.

- Artifact-era rollback and retained-release restoration select the exact
  root-owned helper contract and Nginx template for the target release. The
  newest trusted verifier performs validation; older helper code is never
  executed.
- A bounded `--restore-retained` operation restores an already protected
  release from local evidence when GitHub is unavailable, without rebuilding,
  rewriting the archive, or relaxing new-candidate checks.
- The isolated regression covers v1.4.3 to v1.4.7 origin promotion, a failed
  independent-network gate, and restoration of v1.4.3 with its own helper and
  Nginx contract. Separate cases prove artifact-era rollback and legacy v1.4.1
  recovery behavior.
- Artifact packing and recovery fixtures cover umasks `0027` and `0077`. The
  runtime manifest is normalized to `0644`, and the complete tree is
  revalidated before packaging.
- The post-copier acceptance fixture now creates a known `0755` destination and
  preserves every reviewed artifact mode while copying. This prevents a
  restrictive builder umask from making the copied tree unreadable to the
  separate service or Nginx identities, and the copied tree is still verified
  against the original archive before execution.
- The current Nginx template uses `http2 on` instead of the deprecated
  `listen ... http2` parameter. The exact v1.4.1 rollback template remains
  unchanged. CI validates current syntax with the fingerprint-verified official
  Nginx package because Ubuntu 24.04's distribution package predates the
  standalone directive.
- Documentation distinguishes deterministic local origin acceptance from
  independent WAN acceptance. NAT hairpin behavior is never reported as
  outside-client evidence.

The direct host remains `zilch-site` on `127.0.0.1:3018` with Node 24.18.1.
NP Service Request remains on `127.0.0.1:3016`. This source release does not
change DNS, credentials, databases, firewall policy, or production state.
