# Zilch 1.4.10

## Bounded archive verification and deployment requirements

- Both archive-backed extraction and verification now bound compressed input, decompressed TAR data, metadata headers, and the runtime manifest before Python's TAR parser materializes them. Size-altering PAX or sparse metadata, negative member sizes, and nonzero trailing content are rejected.
- Regression tests cover malicious PAX metadata, aggregate limits, size overrides, negative headers, an oversized manifest, concatenated Gzip data, and legitimate long-path PAX archives. The previous v1.4.9 release archive remains readable by the new verifier.
- The accepted artifact receipt now includes a machine-readable deployment contract: application and exact artifact identity, runtime and architecture, required direct-host adapter capabilities, health/readiness paths, and the no-migration rollback rule. The host must compare these requirements with its installed capabilities before activation; this source release does not change host configuration or grant permission to do so.

The direct host topology, protected paths, service account, ports, Nginx policy, and retained rollback rules remain unchanged. Source and CI validation do not establish production activation.
