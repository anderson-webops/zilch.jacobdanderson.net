# Zilch 1.4.7

This release supersedes the unpublished `v1.4.4`, `v1.4.5`, and `v1.4.6`
candidates after their Linux ARM64 gates exposed portability and rollback-test
issues before publication. Existing tags remain immutable.

It retains and completes the deployment hardening introduced by those
candidates:

- runtime artifact manifests independently enforce required paths, hashes,
  source identity, and installed modes, with clean unpacked-artifact tests;
- root extraction keeps runtime and static files readable by the distinct
  service and Nginx identities while the private preparation marker remains
  root-only;
- privileged ownership uses numeric root UID and GID values and does not depend
  on an account-name database;
- exact `v1.4.1` rollback compatibility uses `/api/health` and the historical
  Nginx contract, while every newer release requires `/healthz` and `/readyz`;
- legacy edge-probe success and failure now return explicit shell statuses, so
  rollback acceptance behaves consistently across architectures;
- the bounded synthetic recovery subprocess allows 45 seconds on slower native
  runners without changing production probe, retry, rollback, or acceptance
  policy; and
- normal branch validation now exercises the privileged promotion and recovery
  suite on Linux ARM64 before a release tag is created.

Validation covers the frozen Node 24.18.1 and npm 12.0.2 dependency graph, full
and production audits, registry signatures, Linux ARM64 native packages, lint,
types, 85 automated tests, both builds, deployment and Netlify contracts, the
production-only API install, accessibility smoke checks, the disposable
privileged host, and all 30 synthetic promotion and recovery scenarios. The
tagged workflow remains authoritative for the exact Linux ARM64 release
artifact and its acceptance receipt.

This is source delivery only. Production activation remains a separately
authorized server operation. Local origin probes are not independent WAN
acceptance, and this release does not change DNS, the reviewed Zilch port, or
the separate NP Service Request application.
