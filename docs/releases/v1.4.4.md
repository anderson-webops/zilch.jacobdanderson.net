# Zilch 1.4.4

## Artifact activation and rollback compatibility

- Root extraction now normalizes release directories to `0755`, service and
  static files to `0644`, and the private prepared marker to root-owned `0600`.
  The disposable-host regression starts the extracted candidate under the
  distinct `zilch-site` UID and verifies static readability under the distinct
  Nginx worker UID.
- Runtime manifest format 2 records and independently enforces installed file
  modes. Format 1 is rejected for archives and new candidates; its explicit
  compatibility flag applies only to direct verification of an already
  installed artifact-era rollback tree.
- Pre-artifact rollback is restricted to v1.4.1 at
  `fc43e474c0c402fdea39828e02a59cab9aa60661`. That exact target uses its real
  `/api/health` contract, rejects the absent modern probe routes in recovery
  fixtures, and atomically restores its historical Nginx server block. Forward
  activation installs the pinned current server block at a fixed production
  path, and the recovery regression proves a second forward promotion after a
  compatibility rollback.
- All newer targets continue to require direct and edge liveness, readiness,
  identity, TLS, header, redirect, and unknown-route checks.
- Production activation remains artifact-only. Source validation refuses
  production release trees, the obsolete `.zilch-runtime.sha256` generator is
  removed, and the runbook requires successful tagged CI provenance, the
  unchanged Linux ARM64 archive, installed-contract verification, and a
  disposable-port start as `zilch-site` before promotion.

Local validation covered a clean Node 24.18.1/npm 12.0.2 locked install, zero
full-graph and production advisories, verified registry signatures, native
bindings, lint, types, 84 automated tests, both builds, deployment and Netlify
checks, production dependency trees, and accessibility across desktop, dark
mode, mobile reflow, and both routes. The tagged Linux workflow remains
authoritative for all 29 isolated promotion/recovery scenarios, the disposable
root-host regression, and the exact Linux ARM64 artifact.

This is a source release. It does not deploy production, change DNS or Nginx by
itself, move Zilch from `127.0.0.1:3018`, or modify NP Service Request on
`127.0.0.1:3016`. Local origin checks are not represented as independent WAN
acceptance.
